# `Configuration/`

Точка входа — `main.yml`. Он объявляет `title` и последовательность `actions`: `!writeStatus` между фазами и `!task` на фазовые файлы.

**Статус:** пусто до v0.1.

Структура, к которой проект идёт:

| Файл | Содержимое | Этап исполнения |
|---|---|---|
| `main.yml` | оркестратор: статусы и `!task` | injection + OOBE |
| `Tasks/00-preflight.yml` | снятие prior-state, проверки окружения | OOBE |
| `Tasks/10-registry.yml` | параметры реестра | injection + OOBE |
| `Tasks/20-services.yml` | тип запуска и удаление служб | преимущественно injection |
| `Tasks/30-appx.yml` | удаление мусорных Appx | OOBE |
| `Tasks/40-tasks.yml` | запланированные задачи | OOBE |
| `Tasks/50-privacy.yml` | телеметрия и потребительский слой | injection + OOBE |
| `Tasks/60-invariants.yml` | явная проверка нетронутых компонентов | OOBE |
| `Tasks/90-report.yml` | манифест изменений и верификатор | OOBE |

Правила:

1. Порядок `!task` в `main.yml` — единственный механизм порядка. Менять его осознанно.
2. Гейты: `option` / `options` на действии или на `!task`; `builds` для сборок; `iso` / `oobe` для этапов.
3. Данные и логика — только через `!action`. Никакой условной логики в YAML нет: условия выражаются гейтами.
4. Каждый файл задач соответствует одной фазе и одной категории изменений.
