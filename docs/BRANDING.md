# Фирменный стиль BareOS

Замысел владельца от 2026-11-11, решение — [DECISIONS](DECISIONS.md) D-028. Название продукта сменено владельцем на **Bare OS** (в знаке и именах файлов — `BareOS`); переименование кода и документов выполнено (D-029): CLI `bareos`, проекты `BareOS.*`. Это концепция и дизайн-документ; реализация — в конце проекта, после движка, playbook и каркаса Toolbox ([ROADMAP](ROADMAP.md)). Исполнитель реализации — агент `designer` (`.claude/agents/designer.md`).

## 1. Принципы

1. **Бренд виден сразу после установки**: обои, тема, акцент, экран блокировки и Toolbox складываются в одну узнаваемую картинку, как у ReviOS и AtlasOS.
2. **Бренд — такие же карточки, как твики.** Каждое изменение оформления — карточка `brand.*` в каталоге движка ([PARAMETERS](PARAMETERS.md)) со снимком исходного состояния, проверкой и откатом. Отдельных скриптов оформления нет (D-023).
3. **Только своё.** Все изображения, знак и иконки рисуются в репозитории из исходников (SVG и скрипт рендера). Чужие обои, логотипы, шрифты и иконпаки не используются.
4. **Системные файлы не трогаются.** Не заменяются `img0.jpg`, `imageres.dll`, загрузочный логотип, системные звуки и курсоры: это файлы TrustedInstaller, их возвращают SFC и обновления, а замена ломает D-019.
5. **Пользователь не заперт.** Оформление ставится как обычная пользовательская настройка, без политик, блокирующих смену обоев или экрана блокировки.

## 2. Как это делают другие

### 2.1. Что видно у ReviOS и AtlasOS

| Проект | Что видно после установки | Уверенность |
|---|---|---|
| ReviOS | красные фирменные обои, тёмная тема, сведения о системе в «Параметры → О системе», собственная утилита Revision Tool | по публичным материалам и скриншотам; исходники не прочитаны |
| AtlasOS | фирменные обои в нескольких пропорциях (4:3, 16:9, 16:10, 21:9), тёмная тема, папка настроек на рабочем столе, набор бренда на docs.atlasos.net/branding | обои и пропорции — подтверждены страницей бренда; механизм применения не прочитан |

Исходники обоих playbook из этой среды не читаются (GitHub закрыт для автоматического чтения). Перед реализацией `designer` сверяет §2.2 с актуальными `.yml` обоих проектов на машине владельца и обновляет таблицу. Опираться можно только на §2.2: это штатные механизмы Windows, не зависящие от чужого кода.

## 3. Идея

**«Ничего лишнего».** Bare — голый, без обёртки. Система после BareOS выглядит как чистый лист: графит, костяной белый, тонкие линии и один сигнальный цвет. Бренд узнаётся по сдержанности, а не по картинке на весь экран. Никакой магии, огня, неона и «геймерских» углов.

Сигнальный мятный цвет — единственный акцент и одновременно цвет «проверено». Это сделано намеренно: обещание проекта — голая система, в которой каждое изменение доказано (D-014). Где мятный, там подтверждённый факт.

Отличие от соседей: ReviOS — красный и агрессивный, AtlasOS — синий и нейтральный. BareOS — почти монохром с одной мятной точкой.

| Понятие проекта | Образ |
|---|---|
| Чистая система | пустое окно, чистый лист |
| Карточка твика | строка спецификации: что, где, чем проверено |
| Proof Report | мятная отметка |
| Откат | вернуть лист как был |
| Дрейф после обновления | янтарная отметка |

В кнопках и статусах — обычные слова: «Применить», «Вернуть», «Проверено».

## 3a. Изюминка: живой курсор

Серой массы у других сборок много. Запоминаться BareOS должен одной узнаваемой деталью: **мятный курсор «_»**. Это единственный элемент системы, который светится и движется. Увидел мигающий мятный курсор — это BareOS.

| Где | Как выглядит |
|---|---|
| Знак | «b_»: в анимации курсор мигает, в статике остаётся подчёркиванием (эскиз D) |
| Обои | в углу над панелью задач строка-квитанция моноширинным шрифтом: `bare · <сборка> · <проверено>/<всего> проверено_`. Данные настоящие: её обновляет Toolbox после каждого `verify` |
| Экран блокировки | время и мигающий мятный курсор сразу после него |
| Программа установки и Toolbox | применение печатается построчно, как лог: `privacy.diag.level … ✓ проверено`, в конце курсор. Это же и есть журнал прогона |
| Загрузочные тексты, «О программе» | курсор после последней строки |

Правила, чтобы изюминка не превратилась в шум:
1. Курсор мятный и один на экран. Анимация только мигание (≈1,1 с, шаг без плавности) и посимвольная печать журнала.
2. При включённом «Уменьшить движение» курсор не мигает, журнал показывается сразу целиком.
3. Строка-квитанция на обоях — часть картинки, а не окно: без кликов, без уведомлений. Если проверок не было, строка не рисуется (никаких выдуманных цифр).
4. Курсор не заменяет статусы: «проверено» всегда с иконкой и словом (§4).

Техническая сторона: строку на обоях Toolbox вписывает в уже установленное изображение; исходный файл обоев сохраняется для отката. Откат (§9) возвращает обои без строки.

## 5. Типографика

| Назначение | Шрифт | Почему |
|---|---|---|
| Интерфейс Toolbox | Segoe UI Variable (системный) | штатный шрифт Windows 11, ничего не поставляем |
| Журнал, ключи реестра, ID карточек, подписи | Cascadia Mono; запасной — Consolas | открытая лицензия OFL; моноширинный шрифт — часть «голого» характера; наличие в чистой 26H2 требует проверки |
| Знак и надпись BareOS | собственная надпись в кривых (SVG) | не зависит от шрифта |

Шкала — типовые стили WinUI 3 без своих размеров. Моноширинный шрифт шире обычного используется для подписей и идентификаторов: интерфейс показывает «как есть».

## 6. Знак

Четыре эскиза, выбор за владельцем (BQ-04):

| Эскиз | Идея |
|---|---|
| A · Строчная b | одна линия: ствол и открытая чаша; мятная точка — «проверено» |
| B · Пустое окно | тонкий квадрат, заполнен только нижний правый угол мятным: окно без лишнего, одна отметка |
| C · Плитка | графитовая плитка с костяной `b` и мятной точкой — иконка Toolbox и `playbook.png` |
| D · Курсор (рекомендуется) | `b_` моноширинным начертанием: система «как есть», мигающий курсор в анимации; несёт изюминку (§3a) |

| Вариант | Где |
|---|---|
| Полный: знак + надпись BareOS | README, страница AME Wizard, «О программе» |
| Только знак | иконка Toolbox, `playbook.png`, логотип в OEMInformation, favicon |
| Монохромный | экран блокировки, водяной знак обоев, отчёты для печати |

Требования: читается в 16 px (с отдельной оптической версией для 16–24 px); работает в один цвет; не похож на знаки Windows (четыре окна), AtlasOS, ReviOS, Bing и известных брендов на «b» — проверка до утверждения. Исходник один — `branding/src/mark.svg`.

## 7. Обои и экран блокировки

**Сюжет:** графитовый фон с лёгким зерном, тонкие горизонтали-изолинии костяного цвета (рельеф «голой земли») с низкой непрозрачностью, одна мятная отметка и строка-квитанция с курсором в углу (§3a). Почти пусто: обои не спорят с окнами.

| Набор | Содержание |
|---|---|
| `bareos-dark` | основной, по умолчанию |
| `bareos-light` | `Paper` и графитовые изолинии — для светлой темы |
| `bareos-lock` | больше пустого места под часы, мигающий курсор после времени, знак внизу |
| `bareos-plain` | только графит и зерно, без строки-квитанции |

Разрешения: 3840×2160 (16:9), 2560×1600 (16:10), 5120×2160 (21:9), 2732×2048 (4:3). Формат — JPEG качества 92: размер `.apbx` ограничен ([PLAYBOOK-CONF](PLAYBOOK-CONF.md) §7). Обои — **генерация скриптом** из параметров (`tools/branding/render`), результат воспроизводим и не зависит от сторонних изображений или генеративных моделей с неясной лицензией.

## 8. Что применяется при установке

FeaturePage «Оформление» в playbook, три варианта:

| Вариант | Состав | По умолчанию |
|---|---|---|
| Полное | все карточки ниже | да |
| Только тема | тёмный режим и акцент, без обоев и экрана блокировки | — |
| Не менять | ничего из `brand.*`; Toolbox и его ярлык ставятся всё равно | — |

Карточки (все T1, класс устойчивости A, статус `proposed`):

| ID | Что делает | Область |
|---|---|---|
| `brand.assets.files` | копирует обои и `BareOS.theme` в `%WINDIR%\Web\Wallpaper\BareOS\` и `%WINDIR%\Resources\Themes\` | машина |
| `brand.theme.dark` | тёмный режим системы и приложений | пользователь + Default |
| `brand.accent.color` | акцент `#3DDC97`, акцент в заголовках выключен | пользователь + Default |
| `brand.wallpaper.desktop` | обои `bareos-dark` под пропорцию экрана | пользователь + Default |
| `brand.lockscreen.image` | `bareos-lock` через API LockScreen | пользователь |
| `brand.oem.info` | `Manufacturer = BareOS`, `SupportURL` = страница проекта, `Logo` — знак; только при пустом ключе | машина |
| `brand.toolbox.shortcut` | ярлык Toolbox в «Пуске» | пользователь |

`brand.assets.files` — зависимость остальных; без неё ни одна карточка не применяется. Подбор обоев под пропорцию — по основному монитору на момент применения.

## 9. Откат

Подчиняется [REVERT](REVERT.md) и [EXECUTION-CONTRACT](EXECUTION-CONTRACT.md) без исключений:

1. Перед применением движок снимает исходные значения всех затронутых ключей, путь текущих обоев и текущей темы.
2. Откат возвращает значение, **только если текущее равно нашему**. Если пользователь после установки сам сменил обои или акцент, откат их не трогает и пишет «изменено пользователем, оставлено».
3. Файлы из `brand.assets.files` удаляются последними, после того как ни одна настройка на них не ссылается.
4. Toolbox: «Откат и отчёты → Оформление → Вернуть оформление Windows» — один прогон `revert` по всем `brand.*`.
5. Верификатор проверяет и применение, и откат: значения реестра, наличие файлов, путь текущих обоев.

## 10. Toolbox

Основа — стандартный Fluent / WinUI 3. Бренд выражается токенами, а не нестандартными контролами: так приложение выглядит «родным» и не ломается при обновлениях WinUI.

| Элемент | Решение |
|---|---|
| Фон окна | Mica (Mica Alt для области вкладок); при отключённой прозрачности — `Ink` / `Parchment` |
| Навигация | `NavigationView` слева, вкладки из [TOOLBOX](TOOLBOX.md) §2 |
| Акцент | собственные `AccentFillColor*` поверх системных ресурсов: акцент Toolbox мятный, даже если в Windows другой; текст на акцентных кнопках графитовый |
| Тема | следует системной; переключатель в настройках Toolbox |
| Иконки | Segoe Fluent Icons (системные) + несколько своих глифов: отметка «проверено», откат |
| Карточка твика | заголовок, риск (T1–T3 чипом), класс устойчивости, статус, «что ломает» раскрывается, кнопки «Применить» / «Вернуть» |
| Статусы | «Проверено» — `Signal` + отметка; «Дрейф» — `Ember`; «Ошибка» — `Hex`; «Не применено» — нейтральный |
| Обзор | крупная отметка состояния: сколько карточек применено, сколько проверено, есть ли дрейф |
| Движение | стандартные переходы WinUI; одна фирменная анимация — мятная отметка проявляется при успешной проверке, до 300 мс, отключается вместе с системными анимациями |
| Пустые состояния | изолинии и короткая строка текста, без иллюстраций-персонажей |
| Доступность | контраст по §4, клавиатура везде, экранный диктор читает статусы словами, режим высокой контрастности — системные цвета без бренда |

## 11. Голос и тексты

Точно, коротко, на «вы» в интерфейсе. Говорим, что меняется и что ломается; не обещаем скорость без замера (D-014).

| Так | Не так |
|---|---|
| «Отключено 14 задач телеметрии. Проверено: 14 из 14» | «Система ускорена!» |
| «Вернуть как было» | «Сбросить оптимизацию» |
| «Ломает: поиск в интернете из меню Пуск» | «Может повлиять на некоторые функции» |

Языки — русский, украинский, английский ([TOOLBOX](TOOLBOX.md) §5). Название не переводится: BareOS.

## 12. Ассеты и структура

```
branding/
  src/            исходники: mark.svg, wordmark.svg, palette.json, параметры обоев
  out/            результат рендера (в git не хранится, собирается)
  LICENSE         CC BY 4.0 для изображений; код рендера — под лицензией репозитория
tools/branding/   скрипт рендера: знак во все размеры, обои, playbook.png, .ico, .bmp для OEM
Playbook/Images/  копии готовых файлов для .apbx (кладёт сборка)
```

`palette.json` — единственный источник цветов: из него строятся `.theme`, ресурсы WinUI и обои. Размеры знака: 16, 20, 24, 32, 48, 64, 256 px (`.ico`), 256 px (`playbook.png`), 120×120 BMP (OEM), 44/150/310 px для плиток и пакета MSIX.
