# `playbook.conf` — справочник по свойствам

Файл в формате XML в корне playbook. Это первое, что читает AME Wizard. Полный набор полей сверен по официальной документации AME; поля, встречающиеся только в сторонних playbook, помечены отдельно.

## 1. Обязательные свойства

| Свойство | Назначение | Тип / формат |
|---|---|---|
| `Name` | имя playbook | строка |
| `Username` | автор, отображается в интерфейсе | строка |
| `UniqueId` | уникальный идентификатор, UUID v4 | GUID |
| `ShortDescription` | краткое описание для боковой панели | строка |
| `Title` | заголовок основных страниц | строка |
| `Description` | описание на вводной странице | строка |
| `Details` | описание в окне обновлений | строка |
| `Version` | версия playbook | `1`, `0.1`, `0.0.1` |

**Правило проекта:** `UniqueId` генерируется один раз и не меняется никогда — к нему привязаны обновления и распознавание playbook. Смена `UniqueId` = новый playbook для AME.

## 2. Необязательные свойства

| Свойство | Назначение | Замечание |
|---|---|---|
| `SupportedBuilds` | какие сборки поддерживаются | список строк; сравнение по префиксу билда |
| `Requirements` | требования до запуска | список; см. §3 |
| `FeaturePages` | страницы выбора опций | лимиты в [PLAYBOOK-CONF §5](#5-featurepages) |
| `ProductCode` | код для отображения статуса «verified» | выдаёт AME после ревью |
| `ProgressText` | текст на экране прогресса | должен соответствовать реальным шагам |
| `Git` | ссылка на исходники, источник обновлений | включает проверку обновлений |
| `Website`, `DonateLink` | кнопки в окне обновлений | `Website` показывается только для verified |
| `InstallGuide` | ссылка на инструкцию по установке Windows | используется вместе с `FreshInstall` |
| `PasswordReplace` | пароль, которым заменяются пароли MS-аккаунтов | только при конвертации в локальные |
| `ISO` | настройки при сборке ISO | см. §4 |
| `OOBE` | оформление первого запуска | см. §4 |
| `Software` | список ПО, отображаемый в OOBE | иконки из `Images/` |
| `UseKernelDriver` | использовать драйвер для повышенных привилегий | в большинстве случаев не нужен |
| `SupportsISO` | включает поддержку сборки ISO | обязателен для ISO-пути |
| `EstimatedMinutes` | ориентировочное время применения | **не описан в таблицах документации**, встречается в сторонних playbook — проверить на текущей версии AME |
| `UpgradableFrom` | с каких версий допустимо обновление на месте | **не описан в документации**, встречается в сторонних playbook — проверить |

## 3. `SupportedBuilds` и `Requirements`

`SupportedBuilds` — простой список строк, например `26100`, `26200`, `26300`. Это **не** проверка того, что playbook действительно протестирован на этой сборке, а декларация автора. Правило проекта: сборка попадает в список только после прогона по [TEST-MATRIX](TEST-MATRIX.md), до этого возможность не заявляется.

### Требования (`Requirements`)

| Требование | Поведение |
|---|---|
| `Internet` | нужен доступ в интернет |
| `NoInternet` | требуется отсутствие подключения |
| `Activation` | требуется активированная Windows |
| `FreshInstall` | установка не старше ~40 часов (обходится в UI) |
| `DefenderToggled` | пользователь должен вручную переключить четыре тумблера Windows Security |
| `DefenderDisabled` | Defender нейтрализуется на шаге подготовки; **при ISO-сборке AME удаляет Defender из образа** |
| `UCPDDisabled` | отключение драйвера UCPD на шаге подготовки |
| `NoAntivirus` | блокирует запуск при стороннем антивирусе (`root/SecurityCenter2`) |
| `NoPendingUpdates` | блокирует запуск при ожидающих установки обновлениях |
| `PasswordSet` | требует задать пароль и конвертирует MS-аккаунт в локальный |
| `AdministratorPasswordSet` | требует пароль администратора |
| `PluggedIn` | требует питания от сети на ноутбуках |

**Решения проекта:** используемые требования — `NoPendingUpdates` и `NoAntivirus` (оба снижают вероятность испорченного прогона). `DefenderDisabled` не используется: см. [DECISIONS](DECISIONS.md), D-002. `FreshInstall` не используется — при ISO-пути он избыточен, а при отладке мешает.

## 4. Элементы `ISO` и `OOBE`

### `<ISO>`

| Элемент | Действие |
|---|---|
| `<DisableBitLocker>true</DisableBitLocker>` | отключает автоматическое шифрование устройства на этапе setup (пишется `unattend` с `PreventDeviceEncryption` и `TCGSecurityActivationDisabled`) |
| `<DisableHardwareRequirements>true</DisableHardwareRequirements>` | снимает проверку требований setup (TPM/Secure Boot/CPU) |

**Решения проекта:** `DisableBitLocker = true`, `DisableHardwareRequirements` — **не** используется (см. [DECISIONS](DECISIONS.md), D-003 и D-004).

Побочный эффект `DisableBitLocker`, который надо знать: тот же `unattend`, который пишет AME, содержит `BypassNRO=1`, то есть окно требования сети на OOBE снимается. Это поведение платформы, а не выключенная нами функция; в документации проекта оно фиксируется как известный факт.

### `<OOBE>`

- `<BulletPoints>` — ровно три `BulletPoint` с иконками `Lock`, `Privacy`, `Rocket`. Длины `Title` и `Description` подогнаны под примеры AME, иначе текст обрезается.
- `<Internet>Request</Internet>` — предупредить, но не блокировать; `<Internet>Force</Internet>` — требовать подключение.

**Решение проекта:** `Internet` — `Request`. Причина: `Force` на OOBE означает, что установка без сети не завершится, а весь сетевой стек уже изменён нами; отладка в таком состоянии дороже, чем польза от гарантии сети.

## 5. FeaturePages

Механизм, который в AME заменяет «профили». Каждая страница — выбор, каждый выбранный пункт даёт имя-опцию; действия и целые файлы задач включаются по `option:`.

| Тип страницы | Лимит опций | Особенности |
|---|---|---|
| `CheckboxPage` | 4 | `CheckboxOption IsChecked="true|false"`; `<TopLine>` (максимум 3 на страницу-группу) |
| `RadioPage` | 3 | `IsRequired="true"` и `DefaultOption="..."` обязательны при ISO-сборке |
| `RadioImagePage` | 3 | вариант с картинками |

Правила, полученные из практики платформы:

1. `RadioPage` без `IsRequired` и `DefaultOption` роняет сборку ISO — при injection выбирать некому, и AME получает пустой выбор. **Требует проверки на текущей версии**, но в проекте считается обязательным.
2. Все опции, снижающие безопасность, по умолчанию **выключены** (`IsChecked="false"`).
3. Описание опции обязано прямо говорить, что ломается. Не «может повлиять на производительность», а «ломает WSL2 и Docker Desktop».
4. Порядок страниц — от безобидного к рискованному. Страница с рискованными опциями — последняя.

### Как это используется как «профили»

Профиль = именованный набор опций плюс гейты в YAML:

- опция в `FeaturePages` → пользователь выбирает;
- в `main.yml` файл задачи подключается с `option: <имя>` (или инверсией `!имя`);
- внутри файла задач отдельные действия тоже могут быть помечены `option` / `options`.

В v0.1 профилей нет: один фиксированный набор. Профили вводятся в v0.4 (см. [ROADMAP](ROADMAP.md)), потому что каждая дополнительная опция умножает число путей, которые надо протестировать на 26H2.

## 6. Требования к метаданным проекта

| Требование | Значение |
|---|---|
| `UniqueId` | генерируется один раз, хранится в `docs/DECISIONS.md` |
| `Version` | соответствует тегу релиза; формат AME (`0.1`, `0.0.1`) |
| `ProgressText` | перечисляет реальные шаги; при изменении `main.yml` перепроверяется |
| `Description` | не содержит обещаний производительности |
| `Git` | `https://github.com/OlehHavrilko/WindowsWizard/` — заполняется при первом публичном релизе ([DECISIONS](DECISIONS.md) D-013) |
| `ProductCode` | отсутствует до прохождения ревью AME |
| `playbook.png` | 256 px, в корне `Playbook/` |

## 7. Известные ограничения формата

1. `SupportedBuilds` не валидирует реальную сборку — только заявляет.
2. Нет механизма «обязательных шагов только для конкретной редакции» (Home/Pro): редакция проверяется внутри `!powerShell`, но это уже динамическое действие и только на OOBE.
3. Нет штатного механизма отката и нет журнала prior-state — это делается своими средствами.
4. Нет хука «после успешного применения» — верификатор вызывается как последний `!task` в `main.yml`.
