# Безопасность: инварианты и запреты

Документ формализует границу проекта. Всё, что здесь перечислено, либо обязано остаться неизменным после применения playbook, либо не используется вообще. Верификатор проверяет инварианты как постусловия.

## 1. Инварианты (обязаны сохраниться)

| Инвариант | Почему | Как проверяется |
|---|---|---|
| Загрузка и вход работают | отсутствие загрузки — единственный по-настоящему необратимый сценарий | верификация после OOBE + повторная загрузка |
| Secure Boot и TPM 2.0 включены | требуются античитами и штатной работой 26H2 | состояние не изменилось |
| Состояние VBS / Memory Integrity не изменилось | WSL2, Docker, часть античитов | сравнение с prior-state |
| Гипервизор и `VirtualMachinePlatform` на месте | WSL2 / Docker / Sandbox | наличие и работоспособность |
| Store и Xbox-стек работоспособны | игры, установщики, обновления приложений | запуск Store, присутствие пакетов |
| Windows Update проверяет и устанавливает | обновляемость и безопасность | проверка обновлений |
| Драйверы на месте | AMD-стек, стабильность | отсутствие потерь в списке драйверов |
| `root/SecurityCenter2` не содержит нового антивируса | отсутствие неожиданного ПО | перечисление продуктов |
| Нет ни одного параметра, который мы не устанавливали и не можем объяснить | чужое вмешательство или остаток | сверка отчёта с журналом изменений |
| Нет остатков «управляется организацией» от наших политик | иначе пользователь не сможет изменить настройку | проверка политик и текста в интерфейсе |

## 2. Защищённый перечень: не меняется

| Слой | Что именно |
|---|---|
| Ядро и загрузка | конфигурация загрузки, WinRE, драйверы загрузки, службы загрузки (`SERVICE_BOOT_START`) |
| Безопасность | Defender и подсистема безопасности, VBS/HVCI, Credential Guard, политики безопасности, аудит |
| Виртуализация | гипервизор, `VirtualMachinePlatform`, компоненты WSL2, службы контейнеров |
| Компонентный склад | WinSxS, component store, servicing-состояние |
| Идентичность | подсистема входа, профили, реестр пользователей кроме собственных настроек |
| Инфраструктура ОС | RPC, DCOM, журнал событий, планировщик, WMI, управление службами |
| Сеть | сетевой стек, брандмауэр, разрешение имён, VPN-компоненты |
| Драйверы | пакеты драйверов, их файлы и ключи, реестр классов устройств |
| Оболочка | Проводник, поиск, оболочка входа, Store-инфраструктура |

## 3. Службы: политика allowlist

**Запрещено** изменять службы по принципу «список запрещённых из интернета». Именно так ломают установщики и обновления.

Служба допускается к изменению, только если одновременно выполнено:

1. Не имеет типа запуска `BOOT_START` / `SYSTEM_START`.
2. Нет зависимых служб, которые без неё деградируют (проверяется по графу зависимостей).
3. Нет известных потребителей в нужных нам сценариях: игры/античиты, WSL2, Docker, локальный AI, VS Code, Store, обновления, драйверы AMD.
4. Есть prior-state (тип запуска, состояние, конфигурация восстановления) для отката.
5. Изменение не влияет на вход в систему, сеть и обновления.
6. Запись в [DECISIONS](DECISIONS.md) с обоснованием, что именно перестаёт работать.

Отдельно: **перевод в `disabled` — не то же самое, что `manual`**. `manual` обратим без последствий, `disabled` ломает автозапуск по требованию приложения. По умолчанию используется минимально достаточное вмешательство.

## 4. Запрещено полностью

| Запрет | Причина |
|---|---|
| Удаление Windows Defender | необратимо, ломает совместимость; политики при Tamper Protection молча не работают ([DECISIONS](DECISIONS.md) D-002) |
| Отключение Windows Update | неисправимые дыры |
| Удаление Store и Xbox-стека | ломает игры и установщики |
| Отключение гипервизора / `VirtualMachinePlatform` | ломает WSL2, Docker, Sandbox |
| Отключение VBS / Memory Integrity по умолчанию | ломает античиты и контейнеры; допускается только как опция Lab ([DECISIONS](DECISIONS.md) D-022) |
| Работа с WinSxS и component store вручную | разрушает обслуживание системы |
| Правка BCD и WinRE | риск незагружаемой системы без пути назад |
| `takeown` / `icacls` на системные каталоги | нарушает модель доверия |
| Ручное вмешательство в Driver Store и файлы драйверов | ломает установку и обновление драйверов; установка штатным установщиком производителя разрешена ([DECISIONS](DECISIONS.md) D-018) |
| Удаление `!systemPackage` в v0.1 | самый необратимый слой ([DECISIONS](DECISIONS.md) D-008) |
| Отключение mitigations CPU по умолчанию | снижает защиту; допускается только как опция Lab с замером ([DECISIONS](DECISIONS.md) D-022) |
| Одноразовые команды вне `Executables/` | не проходят валидацию, не попадают в отчёт, не откатываются |

## 5. Риск «нет отката» как свойство платформы

У AME нет снапшотов и undo. Это значит, что уровень риска каждого изменения выше, чем в системе с транзакциями:

1. Перед первым прогоном обязателен снапшот ВМ. Для реальной машины — образ системы.
2. Всё необратимое перечисляется в отчёте **до** применения, а не после.
3. T3-решения по умолчанию выключены и включаются осознанно.
4. Откат проектируется заранее ([REVERT](REVERT.md)), а не пишется «если что».

## 6. Типовые сценарии отказа и защита от них

| Сценарий | Как предотвращается |
|---|---|
| playbook падает на разборе из-за несовместимого `iso:` | офлайн-валидатор до упаковки ([BUILD](BUILD.md)) |
| действие молча не применилось | верификатор как последняя фаза ([VERIFICATION](VERIFICATION.md)) |
| удалили приложение, нужное для игры/драйвера | список кандидатов только с обоснованием, Store/Xbox сохранены |
| служба отключена и что-то перестало устанавливаться | allowlist + проверка зависимостей + сценарии из [TEST-MATRIX](TEST-MATRIX.md) |
| обновление Windows сломало конфигурацию | обновления не отключаются; проверка постусловий после обновления — отдельный прогон |
| политика не снимается после отката | фиксируется, какие ключи политик мы создали; откат удаляет их целиком |
| после прошивки BIOS машина просит ключ BitLocker | шифрование на ISO-пути отключено ([DECISIONS](DECISIONS.md) D-003) |
| чужой антивирус вмешался в прогон | требование `NoAntivirus` |
| прогон на системе с незавершёнными обновлениями | требование `NoPendingUpdates` |

## 7. Ответственность

Playbook — не средство резервного копирования и не страховка. Пользователь обязан:

1. Иметь снапшот ВМ или образ системы до первого прогона.
2. Хранить отчёт и журнал prior-state вместе с резервной копией.
3. Не применять на машине, где нет возможности переустановить систему.
