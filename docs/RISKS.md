# Риски и их снижение

## 1. Риски платформы

| ID | Риск | Влияние | Снижение |
|---|---|---|---|
| R-01 | AME Wizard — Beta, формат и поведение меняются | playbook перестаёт собираться или применяться | пиновать версию AME; валидатор как страховка; минимум динамических действий |
| R-02 | У платформы нет отката | любая ошибка остаётся в системе навсегда | снапшот до прогона, свой сценарий отката, пункт приёмки ([REVERT](REVERT.md)) |
| R-03 | Действие молча не применяется | пользователь считает, что настройка есть | верификатор с постусловиями ([VERIFICATION](VERIFICATION.md)) |
| R-04 | Несовместимое `iso:` ломает разбор целиком | релиз не загружается у пользователя | офлайн-валидатор до упаковки ([BUILD](BUILD.md)) |
| R-05 | Лимиты FeaturePages упираются при росте опций | приходится резать функциональность | группировка опций заранее, решение по профилям в v0.4 |
| R-06 | `RadioPage` без обязательных атрибутов роняет сборку ISO | ISO не собирается | правило в [PLAYBOOK-CONF](PLAYBOOK-CONF.md) §5 + проверка в валидаторе |
| R-07 | Нет условной логики | часть сценариев выражается только скриптами | проверочные сценарии сообщают о несовместимости вместо обхода |

## 2. Риски ОС и конфигурации

| ID | Риск | Влияние | Снижение |
|---|---|---|---|
| R-08 | 26H2 = 26300 не подтверждён | заявленная поддержка ложная | подтвердить `winver`; до этого сборка не в `SupportedBuilds` |
| R-09 | Обновление Windows перезаписывает настройки | конфигурация дрейфует | обновления не отключаются, постусловия проверяются после обновления (S-09) |
| R-10 | Отключённая служба ломает установщик или игру | неочевидный отказ через недели | allowlist по зависимостям и потребителям ([SAFETY](SAFETY.md) §3) |
| R-11 | Удалённый Appx нужен для игры, драйвера или разработки | необратимая потеря функциональности | удаляется только явный мусор; Store и Xbox-стек сохраняются |
| R-12 | Политика не снимается после отката | пользователь не может изменить настройку | удаление параметров политик целиком, а не обнуление; проверка остатков |
| R-13 | Внешнее управление (домен, MDM, EDR) конфликтует с playbook | часть настроек не применяется или перебивается | детект в preflight, конфликт фиксируется, а не перебивается |
| R-14 | Tamper Protection делает «отключение Defender» фиктивным | опция есть, эффекта нет | Defender не трогаем вовсе ([DECISIONS](DECISIONS.md) D-002) |
| R-15 | Автошифрование диска на 24H2+ приводит к запросу ключа после апдейта прошивки | машина недоступна | `DisableBitLocker` на ISO-пути ([DECISIONS](DECISIONS.md) D-003) |
| R-16 | Правка offline-реестра расходится с live-состоянием | разные результаты на ISO и на живой системе | раздельные прогоны S-01 и S-05, разная раскладка `iso:`/`oobe:` |

## 3. Риски процесса

| ID | Риск | Влияние | Снижение |
|---|---|---|---|
| R-17 | Расползание набора «ещё один твик» | непредсказуемость, рост числа путей тестирования | чек-лист приёма ([PARAMETERS](PARAMETERS.md) §7), статус `verified` как условие релиза |
| R-18 | Тестирование только на ВМ | физическая машина ведёт себя иначе (драйверы, античиты) | физическая приёмка обязательна перед v1.0 |
| R-19 | Заявления о производительности без измерений | потеря доверия к проекту | критерий эффекта обязателен ([DECISIONS](DECISIONS.md) D-011) |
| R-20 | Один прогон, вывод «всё работает» | дефекты на других конфигурациях | матрица S-01…S-10 и обязательные среды |
| R-21 | Документация расходится с фактическим поведением | опаснее отсутствия документации | документация обновляется тем же изменением, что и `Playbook/` |

## 4. Риски безопасности

| ID | Риск | Влияние | Снижение |
|---|---|---|---|
| R-22 | Ошибочное отключение защитного механизма | компрометация машины | защищённый перечень и запреты ([SAFETY](SAFETY.md) §2, §4) |
| R-23 | Одноразовая команда в обход валидации | неучитываемое изменение | только артефакты из `Executables/`, запрет однострочников |
| R-24 | Неочевидная деградация после «оптимизации» | сломанный рабочий сценарий через недели | инварианты разработчика в верификаторе, прогоны с играми и Docker |
| R-25 | Распространение непроверенного `.apbx` | чужая машина калечится нашим файлом | контрольные суммы, отсутствие публикации до полной матрицы, явные предупреждения |

## 5. Приоритеты

Блокирующие для любого релиза: R-02, R-03, R-08, R-22, R-25. Остальные — управляемые, но требуют записи в [DECISIONS](DECISIONS.md) при принятии остаточного риска.

## 6. Что делать при срабатывании риска

1. Зафиксировать факт в `CHANGELOG` с версией и сборкой.
2. Если риск затрагивает безопасность или загрузку — отозвать релиз ([BUILD](BUILD.md) §8).
3. Добавить проверку, которая поймала бы это раньше.
4. Обновить матрицу тестов, чтобы новый сценарий стал регрессией.
