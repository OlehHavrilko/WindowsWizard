# Тестовая матрица

## 1. Среды

| Среда | Роль | Обязательность |
|---|---|---|
| ВМ, Windows 11 26H2 Pro x64, чистая установка | основной прогон | обязательна |
| ВМ, Windows 11 25H2 Pro (26200), чистая установка | регрессия, если сборка в `SupportedBuilds` | обязательна при заявленной поддержке |
| ВМ, Windows 11 24H2 Pro (26100), чистая установка | регрессия, если сборка в `SupportedBuilds` | обязательна при заявленной поддержке |
| Физическая машина (целевая конфигурация) | финальная приёмка | обязательна перед v1.0 |
| ISO-путь: внедрение playbook в образ → установка с носителя | проверка injection/OOBE | обязательна перед v0.3-релизом |

Параметры ВМ фиксируются: объём диска, число ядер, режим прошивки (UEFI + Secure Boot + TPM 2.0), объём ОЗУ. Снапшот — до каждого прогона.

## 2. Сценарии

| ID | Сценарий | Ожидание |
|---|---|---|
| S-01 | применение на чистой системе | все проверки пройдены, отчёт сформирован |
| S-02 | повторное применение | идемпотентно, изменений нет |
| S-03 | откат после применения | состояние совпадает с исходным (кроме необратимого) |
| S-04 | применение после отката | результат идентичен S-01 |
| S-05 | ISO injection → установка → OOBE | playbook применился на первом запуске |
| S-06 | применение при незавершённых обновлениях | заблокировано требованием `NoPendingUpdates` |
| S-07 | применение при стороннем антивирусе | заблокировано требованием `NoAntivirus` |
| S-08 | применение на системе без TPM/Secure Boot | явное сообщение, отказ от несовместимых блоков |
| S-09 | обновление Windows после применения | система обновляется, ключевые настройки сохраняются |
| S-10 | вход вторым пользователем | пользовательские настройки не применяются к чужому профилю |
| S-11 | сбой preflight / прерывание до отчёта | последующие изменения не выполнены, частичный журнал сохранён, контрольное действие после сбоя не исполнено |
| S-12 | политика или ключ, которых не было | возврат prior-state: удаление созданного, восстановление полного содержимого непустых целей |
| S-13 | повторный и прерванный прогон | исходный baseline не перезаписан, у прогонов свои `run_id`, записи `unknown` сверяются с целью |
| S-14 | контекст пользователя | `HKCU` пишется владельцу (SID), проверены второй пользователь и контекст SYSTEM/администратора; Default User — отдельная цель |
| S-15 | хранение отчётов | путь `%ProgramData%\WindowsWizard\runs\<run_id>\`, ACL, атомарная запись, baseline неизменяем |
| S-16 | публикация отчёта | обезличивание, экранирование, отсутствие ключей/токенов/паролей |
| S-17 | baseline при ISO injection | offline-снимок получен и перенесён средствами сборки; поведение вложенных `!task` не экстраполируется из флага родителя |

Сценарии S-11…S-17 добавлены по ревизии каркаса ([REVIEW](REVIEW.md)) — они проверяют контракт исполнения ([EXECUTION-CONTRACT](EXECUTION-CONTRACT.md)), а не только конечное состояние.

## 3. Проверки после каждого прогона

### 3.1 Загрузка и базовая работоспособность

| Проверка | Ожидание |
|---|---|
| Загрузка | успешно, без цикла восстановления |
| Вход | успешно, профиль цел |
| Журнал событий | нет новых критических ошибок, связанных с изменениями |
| Сеть | есть, разрешение имён работает |
| Проводник и оболочка | запускаются, контекстные меню работают |
| Поиск | работает (если не менялся) |

### 3.2 Стек разработки (обязательно)

| Проверка | Ожидание |
|---|---|
| `wsl --status` | подсистема доступна, версия 2 по умолчанию |
| Запуск дистрибутива WSL | успешно |
| Docker Desktop | стартует, движок поднимается |
| Hyper-V / `Get-VMHost` | доступен |
| Windows Sandbox | доступен (если был) |
| VS Code | запускается, расширения не отвалились |
| GPU-ускорение | доступно, драйвер отвечает |

### 3.3 Игры и Store

| Проверка | Ожидание |
|---|---|
| Store | открывается, установка приложения проходит |
| Xbox-приложения | запускаются |
| Игра с EAC/BattlEye | запускается (или помечена как непроверенная) |
| Игра с Vanguard | запускается (требует Secure Boot + TPM) |
| Secure Boot, TPM | включены, состояние не изменилось |

### 3.4 Обратимость и чистота

| Проверка | Ожидание |
|---|---|
| Откат | состояние совпадает с исходным |
| Остатки политик | нет параметров, которых не было в плане |
| Текст «управляется организацией» | отсутствует в затронутых разделах |
| Файлы отчёта | на месте, читаемы |

## 4. Форма фиксации результата

На каждый прогон — запись:

| Поле | Содержание |
|---|---|
| Дата, версия playbook, версия AME | — |
| Среда | сборка, редакция, ВМ/физическая |
| Хеш базового ISO | — |
| Сценарий | S-01…S-10 |
| Результат | пройден / провален |
| Провалы | ID проверок и фактические значения |
| Отчёт и preflight-снимок | пути |
| Замечания | что требует доработки |

Артефакты прогонов — в `tests/artifacts/` (в репозиторий не коммитятся).

## 5. Что считается провалом релиза

1. Любой несохранённый инвариант из [SAFETY](SAFETY.md).
2. `mismatch` в верификаторе.
3. Непроходимый откат.
4. Неидемпотентный повторный прогон.
5. Потеря работоспособности WSL2, Docker, Store или драйверов.
6. Падение загрузки — без обсуждений, релиз блокируется до выяснения причины.

## 6. Статусы

| Статус | Значение |
|---|---|
| `untested` | не прогонялось |
| `pass` | пройдено, артефакты приложены |
| `fail` | провал, есть задача на исправление |
| `n/a` | неприменимо к текущей конфигурации (например, Docker не установлен) |

На момент создания документации все проверки — `untested`: контента ещё нет.
